**Status:** Inventory screens running against the live API · **Phase:** 7 of 13
**Stack:** Next.js 15.5 (App Router), React 19, TypeScript 5.9, Tailwind 4

---

## 1. The contract chain

The headline of this phase is not a screen. It is that a backend change now
*cannot* silently break the frontend:

```
ASP.NET endpoints
  → contracts/openapi.json        generated from the running host
                                  ContractGenerationTests fails on drift
    → packages/api-client/src/schema.ts   generated by openapi-typescript
                                          CI fails if regeneration changes it
      → packages/api-client/src/index.ts  hand-written, typed against schema
        → apps/web                        typed against the client
```

Every arrow is verified. ADR-0010 promised that a front-end/back-end type
mismatch would be a failing build rather than a runtime `undefined`; this is the
mechanism, and it is tested in both directions.

**Regenerating after a backend change:**

```bash
UPDATE_CONTRACT=1 dotnet test backend/tests/MautoDesk.IntegrationTests && pnpm --dir frontend generate:client
```

### 1.1 Two contracts, on purpose

| File | What it is |
| --- | --- |
| `contracts/openapi.json` | **Generated.** The published contract. What the client is built from. Never hand-edited |
| `contracts/openapi.design.yaml` | The Phase 4 **design spec**. Still covers deals, documents, signatures and everything else not yet built. A target, not a description |

They are deliberately separate. Collapsing them would either delete the design
work or publish a contract describing endpoints that do not exist.

### 1.2 A bug this caught immediately

The first generated client silently typed everything as `any`. Two causes, both
found by building rather than by reading:

1. Endpoints returned `IResult`, so ASP.NET could infer **no response schemas at
   all** — the document had request bodies and nothing else. Fixed by declaring
   `.Produces<T>()` on every endpoint.
2. `schema.d.ts` was emitted as a declaration file, and `tsc` does not copy
   `.d.ts` *inputs* into `outDir` — so `dist/index.d.ts` referenced a module that
   was never published, and every type degraded to `any`. Fixed by generating
   `schema.ts` instead.

Either would have produced a client that compiled perfectly and typed nothing.

## 2. Structure

```
frontend/
  apps/web/
    app/
      layout.tsx                  app shell: rail, header, skip link
      inventory/page.tsx          the grid
      inventory/[vehicleId]/      vehicle detail
    components/primitives.tsx     StatusDot, AgingIndicator, Note, ReadinessMeter
    lib/api.ts                    server-only client factory (BFF boundary)
  packages/
    api-client/                   generated schema + typed client + formatters
    ui/                           tokens.css + the contrast test
```

---

## 3. Decisions

| Decision | Reasoning |
| --- | --- |
| **Server Components, no client-side fetching yet** | The grid and detail views are reads. Server rendering keeps the token on the server and ships less JS — first load is 105 kB. React Query arrives with the first genuinely interactive screen, not before |
| **`lib/api.ts` imports `server-only`** | Makes "never call the API from the browser" a build error instead of a code-review comment. The BFF boundary is enforced by the compiler |
| **`formatMoney` takes a string and never parses it** | The server sends `"28995.00"` precisely so no client rounds a price through an IEEE-754 double. `Number()` in a formatter would reintroduce exactly the bug the string representation prevents |
| **Tailwind mapped onto the design tokens** | `@theme inline` exposes only the *semantic* tokens. Exposing the raw palette would let someone write `bg-slate-300` and bypass the semantic layer, which is how a design system quietly stops being one |
| **Permission checks decide rendering only** | The API omits cost and gross entirely for a caller without the permission. The client check exists so the *column header* is absent too — a permission-shaped screen, not a broken one |

## 5. Gaps

| Gap | Plan |
| --- | --- |
| **No authentication.** `lib/api.ts` sends dev headers from env | Phase 8 replaces them with a session-backed bearer token |
| No mutations from the UI | Add vehicle, change status, publish are rendered but inert. They need a form + Server Actions, which is the next slice |
| No React Query, no optimistic updates | Deliberate: nothing is interactive enough yet to need them |
| No component tests, no Playwright | Verification is currently HTTP-level against the running app. Component tests land with the first interactive screen |
| No dark-mode toggle in the app | Tokens support it fully; the app follows `prefers-color-scheme` and has no control yet |
| Mobile lot-walk screens not built | Designed in Phase 5 §8; needs camera and upload, which needs the photo module |

## 6. Running it

Three processes. Database and API first:

```bash
docker compose up -d postgres && docker compose run --rm migrate
```

```bash
docker exec mautodesk-postgres psql -U postgres -d mautodesk -c "alter role mautodesk_app with password 'devpw';"
```

Then the API, and the web app against it:

```bash
dotnet run --project backend/src/MautoDesk.Api
```

```bash
pnpm --dir frontend dev
```

`apps/web/.env.local` supplies `API_BASE_URL` and the dev tenant/permission
headers. Changing `DEV_PERMISSIONS` is the fastest way to see the
permission-shaped UI rules behave — drop `inventory.cost.read` and the Cost
column disappears rather than greying out.
